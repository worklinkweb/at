筆記：從視覺提案到互動邀請網頁：設計交付與功能驗收

日期：2026-11-25｜關鍵字：網站開發、視覺設計、功能驗收、AI 協作

做什麼

把活動需求轉成 AI 開發工具能照做的網頁規格。

怎麼做

  1. 用 ChatGPT 提出視覺方案與互動示意。
  2. 生成設計圖，連同完整提示詞交給 Work。
  3. 比對實際網頁落差，補修正與驗收指令。

學到什麼

  1. 只給文字提示詞，不一定能還原設計。
  2. 畫面做出來，不代表功能已經完成。
  3. 交付規格要寫資料儲存與驗收條件。

小卡 W-CR-11（AI-011）視覺設計交付

用途：讓 AI 開發工具照設計圖忠實還原畫面與功能。

系別：創造系｜領域：工作職場

適用

  • 互動網頁與活動邀請函。
  • 跨 AI 工具交接開發任務。
  • 已有明確的視覺設計方向。

不適用

  • 需求還沒確認的初期發想。
  • 只需要產出靜態圖片。
  • 不用開發的單純文案任務。

提示詞

請以我上傳的設計圖為正式設計定稿，
忠實還原版面、色彩、文字與操作流程。

請依照以下規格執行：

一、任務目標
［填入使用情境與預期效益］

二、視覺規格
［填入色碼、風格、版面與元件］

三、完整文案
［填入各頁面及按鈕文字］

四、功能規格
［填入操作流程及必要功能］

五、資料處理
［填入儲存、統計及管理權限］

六、驗收條件
［填入可實際操作的測試情境］

七、交付項目
［填入網址、原始碼及操作說明］

不得自行刪除已確認的功能。
不得以靜態畫面取代實際功能。
若有技術限制，請提出可行替代方案。
完成後提供實際畫面與測試結果。

English

Use the uploaded design mockup as the approved visual specification.
Faithfully reproduce its layout, colors, copy, components, and interaction flows.

Follow these specifications:

1. Task objectives
[Use case and expected benefits]

2. Visual specifications
[Color codes, style, layout, and components]

3. Complete interface copy
[Text for every page and button]

4. Functional requirements
[User flows and required features]

5. Data handling and access control
[Storage, reporting, and admin permissions]

6. Acceptance criteria
[Test scenarios that can actually be performed]

7. Required deliverables
[URL, source code, and user guide]

Do not remove approved features.
Do not replace working functionality with static visual mockups.
Explain technical limitations and propose practical alternatives.
Provide actual screenshots and test results after implementation.

使用說明

  • 準備：已確認的完整介面設計圖。
  • 準備：功能規格與完整文案。
  • 限制：設計圖不等於可執行的程式。
  • 提醒：明確指定資料儲存方式。
  • 提醒：要實際測試，才能確認交付品質。

操作步驟

  1. 在 ChatGPT 確認視覺與功能。
  2. 生成完整介面設計圖。
  3. 整理文字、色碼與功能規格。
  4. 把設計圖和提示詞一起交給開發工具。
  5. 檢查實際網頁與設計的落差。

小卡 W-DE-12（AI-012）功能驗收指令

用途：防止 AI 把「畫面做完」誤當「功能完成」。

系別：防禦系｜領域：工作職場

適用

  • AI 開發的互動網頁。
  • 表單與資料統計工具。
  • 跨工具交付的程式專案。

不適用

  • 純靜態圖片。
  • 單純文字創作。
  • 還沒定義功能的概念提案。

提示詞

請依照原始需求檢查目前的成果。

區分以下三個完成層級：

1. 視覺呈現完成。
2. 互動操作完成。
3. 資料儲存與統計完成。

逐項檢查：

- 按鈕是否具有實際功能？
- 操作結果是否正確？
- 資料是否成功寫入後台？
- 不同裝置能否共用資料？
- 修改是否造成重複紀錄？
- 管理權限是否正確？
- 重新整理後資料是否保留？

列出未完成項目並直接修正。

不得將示意畫面宣稱為完成品。
不得將模擬資料宣稱為真實資料。
不得將未測試功能宣稱為驗證完成。

若無法執行測試，請明確標示。

提供實際測試結果及剩餘問題。

English

Review the current implementation against the original requirements.

Distinguish three completion levels:

1. Visual implementation.
2. Working interactions.
3. Persistent data storage and reporting.

Verify that:

- Buttons perform their intended actions.
- Actions produce correct results.
- Data is saved to the backend successfully.
- Multiple devices share the same data.
- Updates do not create duplicate records.
- Access permissions are enforced.
- Saved data persists after refresh.

List incomplete requirements and fix them.

Do not claim that mockups are finished products.
Do not claim that simulated data is real.
Do not claim that untested features are verified.

If you cannot run a test, say so clearly.

Provide actual test results and remaining issues.

使用說明

  • 準備：原始需求與實際成果。
  • 準備：明確的測試情境。
  • 限制：沒有後台權限就無法驗證資料。
  • 提醒：至少用兩個裝置測試。
  • 提醒：驗收後清除測試資料。

操作步驟

  1. 列出原始功能需求。
  2. 比對實際網站與原始規格。
  3. 把每個功能轉成可操作的測試情境。
  4. 要求修正，並提供測試結果。

筆記：畫畫課影片自動剪輯：從成品反推規則再試剪

日期：2026-11-25｜關鍵字：影片剪輯、Claude、工具選擇、AI 協作、AI 作曲

做什麼

用 Claude 在本機把課程原稿剪成初剪，人只確認剪點。

怎麼做

  1. 原稿和剪好的成品比對逐字稿，反推剪輯規則。
  2. Claude 讀逐字稿判斷剪點，做剪點預覽片給剪輯者勾選。
  3. 開源 AI 作曲做配樂候選，程式依片長墊進影片。

學到什麼

  1. 從人剪好的成品反推規則，比自己訂規則準。
  2. 去雜音用 AI 語音隔離，比音量門檻準。
  3. 記憶體不夠時 AI 不一定停下，可能回傳亂猜的結果。

小卡 W-AU-10（AI-010）課程影片初剪

用途：把邊講邊示範的課程原稿，自動剪成去背景音、墊好背景音樂的初剪，並列出剪點給人確認。

系別：自動系｜領域：工作職場

適用

  • 老師邊講邊示範的錄影課，有好幾支原稿要接起來。
  • 已經有一集人工剪好的成品可以當範本。
  • 要固定加系列片頭、片尾。

不適用

  • 需要轉場、特效、字卡的精剪。
  • 沒有講話的純示範影片：逐字稿判斷不了。
  • 要用 AI 生成新畫面的影片。

提示詞

在 Claude Code 打：比對範本、歸納規則

這是同一集課程的原稿和剪好的成品。
請比對逐字稿，列出成品剪掉了哪些內容、保留了哪些，整理成剪輯規則。
先說結論，規則分「要剪」「不剪」「聲音處理」三類。

English

These are the raw clips and the finished edit of the same lesson.
Compare the transcripts, list what the finished edit removed and kept, and turn it into editing rules.
Lead with the conclusion; group rules into "cut", "keep", and "audio".

在 Claude Code 打：試剪新的一集

請用剪輯規則試剪這一集：原稿在 <資料夾>。
片頭片尾用 <檔案>。
輸出初剪影片，並列出剪輯清單（時間、原因、講了什麼），讓剪輯者勾選剪或不剪。

English

Use the editing rules to make a rough cut of this lesson. Raw clips are in <folder>.
Use <files> as the opening and ending.
Export the rough cut and a cut list (time, reason, what was said) for the editor to mark cut or keep.

在 Claude Code 打：做背景音樂候選

範本成品的背景音樂不能匯出用。
請先量範本配樂的音量、速度、風格，再用可商用的開源 AI 作曲做 4 首相近風格的新曲，
每首配一段 60 秒試聽片（含老師聲音），讓剪輯者選 2 首輪流用。
不要拿原曲當參考音訊，只參考風格描述。

English

The background music in the reference edit cannot be exported.
Measure its loudness, tempo, and style, then use a commercially licensed open-source AI music model to make 4 new tracks in a similar style.
Make a 60-second preview with the teacher's voice for each, so the editor can pick 2 to alternate.
Do not use the original track as reference audio; use only the style description.

使用說明

  • 準備：Mac 要先裝 ffmpeg 與 Whisper 環境，第一次約 10 分鐘。
  • 限制：70 分鐘原稿，分析約 15 分鐘、輸出約 12 分鐘。
  • 限制：影片檔很大，不放進 Git 和雲端同步資料夾。
  • 提醒：第一版先保守剪，再依剪輯者的勾選調整。
  • 提醒：剪點清單可先用 XR 請 Codex 依逐字稿抓誤剪。

操作步驟

  1. 準備一集人剪好的成品和它的原稿，請 Claude 比對、整理剪輯規則。
  2. 新的一集：原稿依錄影順序放進同一個資料夾。
  3. 程式分析講話、畫面動作、逐字稿。
  4. Claude 讀逐字稿，標出等學生、重講、講錯、結尾。
  5. 輸出剪點預覽片（紅框＋編號）和審片版（角落標原稿與時間）。
  6. 剪輯者依編號在清單勾剪或不剪，再輸出下一版。
  7. AI 作曲做 3–4 首背景音樂候選和試聽片，剪輯者選 2 首，程式輪流鋪滿全片。

工具與來源

  • FFmpeg：剪接、降噪、音量一致
  • mlx-whisper：本機語音轉文字
  • DeepFilterNet：語音隔離
  • ACE-Step 1.5：本機 AI 作曲、聽音樂寫描述

XC 程式碼審查｜只在 Claude Code 打（指令不用翻譯）

XC

使用說明

  • 準備：ChatGPT、Claude Chat 要先把總說明短版貼進自訂指令，才認得縮寫。
  • 準備：送審前先遮公司名、人名、統編。
  • 提醒：對方沒跑完算「無法驗證」；複驗最多 2 輪。
  • 提醒：XP 舊稱「事前驗屍」，2026-11-25 改成較中性的「風險預演」。

操作步驟

  1. 記法：在哪個 AI 打，就請另一個 AI 來看或來做；打字的 AI 最後判斷。
  2. 顏色：藍色只看不改檔（XR、XP、XV）；紫色會動手改檔（XE、XC）。
  3. XR 交叉審查：文件寫好、想要第二意見時。在 Claude 打由 Codex 審，在 Codex 打由 Claude 審。
  4. XP 風險預演：送審或上線前。做法同 XR，再假設已被退件或失敗，列 5 個原因。
  5. XE 交給 Claude 執行：只在 Codex 打。Codex 寫任務單，Claude 做，Codex 驗收。
  6. XV 唯讀複驗：照審查意見改完後。在哪裡打，就由那個 AI 自己檢查，不叫別的 AI。
  7. XC 程式碼審查：只在 Claude Code 打。Codex 審程式，Claude 修正並重新測試。
  8. 在 ChatGPT 打：XR、XP、XV 由 ChatGPT 自己做；XE、XC 會提醒換工具。
  9. 常見順序：做完 → XR（送審前用 XP）→ 修正 → XV。
  10. AI 會在適合時，於回答最後提示要打哪個縮寫；我打了才執行。

English

Read-only re-check. Do not change any files, and do not call Claude.
Last issue: <issue>. Now changed to: <fix>.
Check only this change, and whether it affects <related screens>. Report pass or fail.

使用說明

  • 準備：Codex 沙盒讀不到鑰匙圈，呼叫 Claude 時要核准在沙盒外執行。
  • 限制：會用到 Claude 方案額度；一件事最多一次跨模型檢查。
  • 限制：完整交辦流程尚未在正式工作驗證。
  • 提醒：對方沒跑完或沒回報，就是「無法驗證」，不是通過。
  • 提醒：每個建議都要逐點判斷，不用會自動照改的工具。

操作步驟

  1. 在 Codex 說「交給 Claude 執行」，寫清楚範圍、可改的檔案和驗收標準。
  2. Codex 存成任務單，用最小權限呼叫 Claude。
  3. Claude 做完回報，Codex 讀實際檔案逐項判斷通過或不通過。
  4. 不通過就修正，複驗只看上次的問題。
  5. 最多複驗 2 輪；還沒通過就停下，把剩下的問題交給我決定。

工具與來源

  • claude-executor：Codex 技能，把任務交給 Claude 並獨立驗收。
  • Codex 官方外掛原始碼（GitHub）
  • Trail of Bits：second-opinion（失敗就算未完成）
  • claude-codex-review（風險預演、限制輪數）
